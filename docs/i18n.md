# Internationalization

Routing and copy are native Next.js 16: locale segment, dictionary API, and Proxy. There is no `next-intl`. JSON message files are the current storage adapter; pages and components call `getDictionary()` / `getDictionaryByLocale()` only. Storage swap: [content.md](content.md).

## Source of truth

[`src/i18n/config.ts`](../src/i18n/config.ts) owns:

- `locales` — supported prefixes
- `defaultLocale` — `en`
- `localeMeta` — native label, `htmlLang`, `dir`
- `hasLocale()` / `getLocaleDirection()` / `isRtlLocale()`

Do not duplicate the locale list in Proxy, layouts, or the language switcher. Import from this file.

## URL rules

| Input | Result |
| --- | --- |
| `/` | Redirect to `/en` or a negotiated locale |
| `/de` | German home |
| `/ar/about` (future) | Arabic page, `dir="rtl"` |
| `/fr` (unsupported) | Treated as a path without a locale → redirect to `/en/fr` (or negotiated) |

Prefixes are always present. English is `/en`, not `/`.

## Files

| File | Role |
| --- | --- |
| `src/i18n/config.ts` | Locale registry |
| `src/i18n/messages/en.json` | Canonical message schema |
| `src/i18n/messages/{de,pt,es,ar}.json` | Translations |
| `src/i18n/messages/assert-complete.ts` | Compile-time key check vs `en.json` |
| `src/i18n/dictionary.ts` | `Dictionary` type (`typeof en.json`) |
| `src/i18n/get-dictionary.ts` | Server copy API (`loadDictionaryFromJson` is the adapter) |
| `src/i18n/pathname.ts` | Swap the locale segment in a pathname |
| `src/proxy.ts` | Prefix missing locales |

## Loading copy

Server Components and server utilities:

```ts
import { getDictionary } from "@/i18n/get-dictionary";

const dict = await getDictionary();
dict.home.title;
```

`getDictionary()` reads `lang` from `next/root-params`. It cannot run in Client Components, Server Actions, or Route Handlers.

When `params` is already available (layout / metadata):

```ts
import { getDictionaryByLocale } from "@/i18n/get-dictionary";

const dict = await getDictionaryByLocale(lang);
```

Client Components must receive strings and `currentLocale` as props.

Do not import `messages/*.json` from a page or component. The JSON files back the loader; they are not a public API.

## Direction

`src/app/[lang]/layout.tsx` sets:

```tsx
<html
  lang={localeMeta[lang].htmlLang}
  dir={getLocaleDirection(lang)}
  style={toCssVars(settings.theme)}
>
```

Theme values come from `getSettings()`, not from locale JSON. See [content.md](content.md).

Arabic is the only RTL locale today. CSS must use logical properties so a new RTL language does not require component rewrites.

## Checklist: add a language

Example: French (`fr`).

1. Add `"fr"` to `locales` in `src/i18n/config.ts`.
2. Add `localeMeta.fr` (`label`, `htmlLang: "fr"`, `dir: "ltr"` or `"rtl"`).
3. If RTL, that is enough — `getLocaleDirection` reads `localeMeta`.
4. Copy `src/i18n/messages/en.json` to `src/i18n/messages/fr.json` and translate values. Keep keys identical.
5. Register the loader in `src/i18n/get-dictionary.ts`.
6. Add `fr` to the object in `src/i18n/messages/assert-complete.ts`.
7. Run `npm run build`. Missing keys fail typecheck.

Proxy, `generateStaticParams`, and SiteHeader’s language Dropdown pick up the new locale from `locales` automatically.

## Checklist: add a string

1. Add the key to `en.json`.
2. Add the same key to every other `messages/*.json` file.
3. Typecheck (`assert-complete.ts` plus `Dictionary`).
4. Pass `dict...` into the component. Do not inline the English string.

## Anti-patterns (agents)

```tsx
// BAD — Client Component calling getDictionary
"use client";
export function Title() {
  const dict = await getDictionary();
  return <h1>{dict.home.title}</h1>;
}

// GOOD — server page loads copy, client receives props
export default async function HomePage() {
  const dict = await getDictionary();
  return <h1>{dict.home.title}</h1>;
}
```

```ts
// BAD — second locale list in a component
const langs = ["en", "de", "ar"];

// GOOD
import { locales } from "@/i18n/config";
```

Do not add `next-intl`, `middleware.ts`, or hide the English prefix (`/` instead of `/en`) without confirmation.
